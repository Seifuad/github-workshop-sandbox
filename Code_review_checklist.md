# Code review checklist

Use this when someone asks you to review their pull request.

- [ ] Read the description. Do you understand what changed and why?
- [ ] Is it linked to an issue?
- [ ] Look at the changed files. Do the changes match the description?
- [ ] Run the code if you can. Does it work?
- [ ] Could a colleague follow the code? Are names clear, and are the tricky parts explained in comments?
- [ ] Are there any passwords, keys, or large or sensitive data files? If yes, ask for them to be removed before merging.
- [ ] Is the README still correct?
- [ ] Leave a comment: one thing that is good, and anything that must change.
- [ ] Approve, or request changes.
